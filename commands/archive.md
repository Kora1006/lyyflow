# /lyyflow:archive —— 归档阶段

## 输入
`$ARGUMENTS` 指定归档命名格式。若为空，使用默认格式 `YYYYMMDD-序号`（如 `20260714-001`）。

## 前置条件

执行归档前，必须满足以下条件：

1. **所有 spec 已完成**：检查 `specs/overview.md` 状态看板，所有 spec 状态均为「已完成」
2. **审核结论全部通过**：每个 spec 的 `## 审核结论` 均为「通过」或「有条件通过」（且条件已满足）
3. **用户确认归档**：询问用户是否确认归档，并确认命名格式

如果条件不满足，列出未完成的 spec 和阻塞项，提示用户先完成。

## 目标
将本次会话生成的需求文档、specs、review 记录等产物打包归档到归档根目录，便于后续追溯和交接。

> **归档根目录**：默认 `~/lyyflow-archives`。用户可指定其他目录（如 `D:/projectSessions`），执行时向用户确认；workflow 编排时通过 `args.archiveRoot` 传入。

## 执行步骤

### 1. 确认归档条件
- 读取 `specs/overview.md`，检查所有 spec 状态
- 验证每个 spec 的审核结论
- 如有未完成项，列出清单并终止归档流程

### 2. 确定归档范围

询问用户确认要归档的内容：

```
即将归档以下内容：
- 需求文档：prd/*.md 或原始需求文件
- specs 目录：specs/spec-*.md、specs/overview.md、specs/api-contracts.md（如有）
- 技术方案、实现记录、审核结论（在 spec 文件内）

是否确认归档？(Y/n)
```

### 3. 确定命名格式

询问用户命名格式，或使用默认：

```
请确认归档命名：
- 默认格式：YYYYMMDD-序号（如 20260714-001）
- 自定义格式：<用户输入>

当前将使用：20260714-001
确认使用此命名？(Y/n/输入自定义命名)
```

### 4. 执行归档

1. **检查并重命名 spec 文件为中文**：
   - 遍历 `specs/` 目录下的所有 spec 文件
   - 如果文件名为英文或编号格式（如 `spec-001-login.md`），重命名为中文格式
   - 中文命名格式：`spec-编号-中文短名.md`（如 `spec-001-用户登录.md`）
   - 从 spec 文件的「详细需求」或标题中提取中文名称
   - 更新 `specs/overview.md` 中的 spec 列表引用

2. **创建归档目录**：
   ```
   ~/lyyflow-archives\<命名>\
   ```

3. **复制文件到归档目录**（保留原始目录结构）：
   ```
   ~/lyyflow-archives\<命名>\
   ├── prd\               # 需求文档（如有）
   │   └── *.md
   ├── specs\
   │   ├── overview.md
   │   ├── spec-*.md      # 已重命名为中文
   │   ├── api-contracts.md（如有）
   │   └── lessons-learned.md（如有，公开快照）
   └── archive-meta.md    # 归档元信息
   ```

   ⚠️ **严格排除** `.lyyflow-local/` 整个目录（含本地教训主版本、会话笔记 `notes/`、hook 源文件）—— 永远不进归档。教训留本地，不进 ~/lyyflow-archives。

4. **生成归档元信息**：
   创建 `archive-meta.md` 记录归档信息（见下方模板）

5. **可选压缩**：
   询问用户是否需要压缩为 zip：
   ```
   是否将归档目录压缩为 zip？(y/N)
   ```

### 5. 完成归档

- 输出归档位置和文件清单
- 询问是否清理当前项目的 `specs/` 目录（保留原文件或删除）

## 归档元信息模板

```markdown
# 归档信息

## 基本信息
- 归档时间：YYYY-MM-DD HH:mm
- 归档命名：<命名>
- 归档位置：~/lyyflow-archives\<命名>\

## 需求概要
- 需求标题：<从 overview.md 提取>
- 需求来源：<从 overview.md 提取>
- 涉及端：<从 overview.md 提取>

## spec 清单

| 编号 | 名称 | 涉及端 | 状态 | 审核结论 |
|------|------|--------|------|----------|
| spec-001 | <名称> | <端> | 已完成 | 通过 |
| spec-002 | <名称> | <端> | 已完成 | 通过 |

## 文件清单
- prd/xxx.md
- specs/overview.md
- specs/spec-001-xxx.md
- specs/spec-002-xxx.md
- ...

## 备注
<用户自定义备注，如有>
```

## 注意
- 归档是**项目级动作**，确保所有 spec 都已完成后再执行
- 归档前建议用户确认命名格式，避免后续查找困难
- **spec 文件必须使用中文命名**，便于后续查阅和理解
- 保留原始目录结构，便于直接查看
- 归档后询问是否清理原文件，避免误删

## spec 文件中文命名规范

归档时，spec 文件命名遵循以下规则：

### 命名格式
```
spec-编号-中文短名.md
```

### 示例
| 原文件名 | 重命名后 |
|----------|----------|
| `spec-001.md` | `spec-001-用户登录.md` |
| `spec-002-login.md` | `spec-002-登录页面.md` |
| `spec-003-api.md` | `spec-003-接口对接.md` |

### 中文名称提取规则
1. 优先使用 spec 文件标题中的中文部分
2. 若标题为英文，从「详细需求」章节提取核心功能的中文名称
3. 名称应简洁明了，不超过 10 个汉字
4. 避免使用特殊字符，仅保留汉字、字母、数字和连字符
